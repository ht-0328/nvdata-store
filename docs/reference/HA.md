# HA — 票数A（枠単）

| | |
| :--- | :--- |
| レコード種別ID | `HA` |
| レコード長 | 1,032 バイト |
| 項目数 | 18 |
| 届くデータ種別 | `RACE` |

## キー

この組み合わせで1件が決まります。

1. 開催年
2. 開催月日
3. 競馬場コード
4. 開催回[第N回]
5. 開催日目[N日目]
6. レース番号

## 繰返しブロック

内訳を持つ繰返しは、DuckDB に入れるときは子テーブルに分けます（jvdata-store と同じ扱い）。

| ブロック | 繰返し | 1回分のバイト数 |
| :--- | ---: | ---: |
| 枠単票数 | 64 | 15 |

## 連番になる項目

内訳を持たない繰返し項目は、連番付きの列に展開します。

| 項目 | 繰返し | 展開後の列名 |
| :--- | ---: | :--- |
| 返還枠番情報(枠番1～8) | 8 | `返還枠番情報(枠番1～8)_1` 〜 `返還枠番情報(枠番1～8)_8` |

## どこで届くか

枠単（1着枠と2着枠を順番どおり当てる券種）を発売する競馬場のレースにだけ付きます。
観測した範囲では浦和・船橋・大井・川崎・金沢です。RACE に RA などと一緒に入ってきます。

## JV-Data の H1 との対応

H1 の 単勝票数 などと同じく、1組が **組番(2)＋票数(11)＋人気順(2)** の 15 バイトです。
枠単は同じ枠の組（1-1 など）も対象なので、組は 8×8＝64 あります。
データ区分は H1 と同じで、観測した範囲では 4（確定）と 9（中止）。

## 確かめ方

- 項目名とバイト数は PC-KEIBA テーブル定義書の `nvd_ha` から取り、合計がレコード長 1,032 と一致することを確かめた。
- 943 件すべてで組番が 11,12,…,18,21,…,88 の順に並び、899 件で票数の和が枠単票数合計と一致した
  （残りは取消のある組が '-' 埋めになっているレース）。
