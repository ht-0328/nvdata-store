# レコードの読み方

**地方競馬DATA の1レコードは、JV-Data と同じ「区切り文字のない固定長のバイト列」です。**
読み方の基本は [jvdata-store の「レコードの読み方」](https://ht-0328.github.io/jvdata-store/02-record-format/) と同じなので、
ここでは**同じところを短く確かめたうえで、違うところを並べます。**

## 同じところ

- 全角は Shift_JIS（cp932）の2バイト、半角は1バイトの固定長。**bytes のまま位置で切ってから cp932 でデコードします。**
  str にしてから切ると、全角1文字＝1で数えられて位置がずれます。
- 先頭3項目はどのレコードも同じ。レコード種別ID（2）・データ区分（1）・データ作成年月日（8）。
- レースを指す鍵は 開催年（4）・開催月日（4）・競馬場コード（2）・開催回（2）・開催日目（2）・レース番号（2）の16バイト。
- 最後は CR/LF の2バイト（レコード区切）。レコード長はこれを含みます。
- 数値は先頭ゼロ埋めの文字列、未設定は 0 埋めか空白、取消などで値がない組は `-` 埋め。

実際に受け取った `RA` の先頭28バイトです。

```
RA72026100320261003540803011
```

| 位置 | バイト | 値 | 項目名 | 意味 |
| ---: | ---: | :--- | :--- | :--- |
| 1 | 2 | `RA` | レコード種別ID | レース詳細 |
| 3 | 1 | `7` | データ区分 | 7 = 成績確定 |
| 4 | 8 | `20261003` | データ作成年月日 | |
| 12 | 4 | `2026` | 開催年 | ← 鍵 |
| 16 | 4 | `1003` | 開催月日 | ← 鍵 |
| 20 | 2 | `54` | 競馬場コード | 54 = 高知。← 鍵 |
| 22 | 2 | `08` | 開催回[第N回] | ← 鍵 |
| 24 | 2 | `03` | 開催日目[N日目] | ← 鍵 |
| 26 | 2 | `01` | レース番号 | ← 鍵 |
| 28 | 1 | `1` | 曜日コード | |

JV-Data の `RA` と同じ位置で同じ意味です。

## 違うところ

### 1. データ区分は「出馬表」と「確定」の2段階しか出ない

JV-Data の `RA` `SE` は 1（出走馬名表）から 7（成績）まで段階を踏みますが、地方では **出馬表の時点で 2、確定と同時に 7** になります。
中間の値は観測した3か月（約8,500レース）で一度も出ませんでした。確定オッズ・票数も同じで、JV-Data の「中間」「前日売最終」にあたる値は出ません。

| レコード | 出る値 | 意味 |
| :--- | :--- | :--- |
| `RA` `SE` | `2` `7` `9` | 出馬表 / 確定 / 中止 |
| `HR` | `2` | 確定 |
| `H1` `H6` `HA` | `4` `9` | 確定 / 中止 |
| `O1`〜`O6` `OA` | `5` `9` | 確定 / 中止 |
| `WF` | `7` | 確定 |
| `NU` | `1` `4` | 新規登録 / その他更新 |
| `NK` `NC` | `2` | 更新 |
| `NN` `NB` `ND` | `1` | 新規登録 |

`0`（削除）は観測していませんが、JV-Data と同じく来るものとして扱ってください。

### 2. コード値に地方特有のものがある

競馬場コード `83`（ばんえい帯広）、トラックコード `90`、競走種別コード `49` と `01`〜`08`、重量種別コード `8` `9`、
グレードコード `P` `Q` `R` `S` `T`、ダート馬場状態コード `5`〜`F`、品種コード `B`、英字の入った競走記号コード。
いずれも JV-Data のコード表にありません。観測した値と推定した意味は [地方特有のコード値](reference/codes.md) にまとめました。

### 3. ばんえいの負担重量と馬体重は16進

ばんえい（競馬場コード `83`）の `SE` では、負担重量（3バイト）と馬体重（3バイト）が **16進** で入ります。
そりの重さは 500kg 台から、馬体重は 1,000kg 前後で、3桁の10進に収まらないためです。

| 項目 | 生の値 | 読み方 |
| :--- | :--- | :--- |
| 負担重量 | `26C` | 16進 → 620 kg |
| 馬体重 | `41B` | 16進 → 1,051 kg |

ばんえい以外の競馬場では10進です。**競馬場コードが `83` のときだけ16進で読む**場合分けが要ります。
走破タイム（`1505` = 1分50秒5）は JV-Data と同じ書き方です。

### 4. 発売のない組は `*` 埋め

JV-Data は取消馬の組を `-` で埋めますが、地方ではそれに加えて、**発売されなかった組（枠連の同枠など）が `*` で埋まります。**
`O1` の枠連オッズ・複勝オッズ・単勝オッズ、`H1` の各票数、`O6` の3連単オッズで観測しました。
数値に直すときは `-` と `*` の両方を「値なし」として扱ってください。

### 5. 馬主コード・生産者コードが `000000` の人が多い

地方の馬主マスタ（`NN`）では、観測した約19,000件のうち約9,000件の馬主コードが `000000` でした。
生産者マスタ（`NB`）も約12,000件のうち約8,000件が `000000` です。コードだけでは誰か決まらないので、
**名前（法人格無）と合わせて鍵にします。** 競走馬マスタ（`NU`）や出走別着度数（`ND`）から馬主・生産者を引くときも同じです。

### 6. 血統登録番号の体系がばんえいだけ違う

サラブレッドの血統登録番号は JV-Data と同じ「生年4桁＋品種1桁＋連番5桁」で、先頭4桁が生年月日の年と一致します。
**ばんえい（品種コード `B`）は一致せず、5桁目が `2`** です。生年を血統登録番号から取らないでください。

### 7. 新旧の種別で繁殖登録番号・生産者の桁が違う

| データ種別ID | 競走馬マスタ地方 `NU` の長さ | 繁殖登録番号 | 生産者コード | 生産者名 |
| :--- | ---: | ---: | ---: | ---: |
| `DIFN`（新） | 1,492 | 10 | 8 | 72 |
| `DIFF`（旧） | 1,460 | 8 | 6 | 70 |

本ドキュメントのレイアウトは `DIFN` の形です。`DIFF` の `NU` は血統登録番号の体系まで違う（同じ馬に別の番号が付く）ので、混ぜないでください。
一方、生産者マスタ地方（`NB`）は `DIFF` でしか届かず、出走別着度数地方（`ND`）は `SNAP` でしか届かないため、この2つは旧サイズ（生産者コード 6、生産者名 70）です。

### 8. 服色標示が2種類ある

地方の騎手マスタ（`NK`）には、勝負服の服色標示が「画像取得用」（`緑，黒縦縞，黒袖緑一本輪` のような区切り付き）と
「文字表示用」（`胴緑・黒縦じま、袖黒・緑一本輪` のような読む人向け）の2種類で入ります。
地方では勝負服が馬主ではなく騎手に付くためで、馬主マスタ地方（`NN`）の服色標示はほとんど空です。

## 読むときの決まり

- **レコード種別IDで表を決め、レコード長で取り違えを検出する。** 同じ ID でも `DIFN` と `DIFF` で長さが違うものがあります。
- **値は仕様の桁のままの文字列で保つ。** `競馬場コード='54'`、`単勝オッズ='0360'`。型変換と意味づけは読む側の責務です（jvdata-store と同じ方針）。
- **16進・`*` 埋め・`000000` の3つは、読む側で場合分けする。** 貯める側では生の値を変えません。
