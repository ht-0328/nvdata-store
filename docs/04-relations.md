# レコードのつながり

**表をどう結合するか**を ER 図でまとめます。鍵の考え方は JV-Data と同じで、地方特有の落とし穴が3つあります。

図の読み方は3つの ER 図とも同じです。

- **箱**が表（レコード種別）。中に並ぶのは結合に関わる項目だけで、全項目は [レコード索引](reference/index.md) から各ページへ。
- **PK** は1件を決める項目、**FK** はほかの表を引く項目。
- **線の文字**が、結合に使う項目。
- **線の端の記号**が、相手1件に対する件数。`||` はちょうど1件、`o|` は0か1件、`|{` は1件以上、`o{` は0件以上。

## レースのまわり

レース単位の表は、JV-Data と同じ**レースキー**（開催年・開催月日・競馬場コード・開催回・開催日目・レース番号、16バイト）で `RA` に結びます。

``` mermaid
erDiagram
    RA["RA レース詳細"] {
        string 開催年 PK
        string 開催月日 PK
        string 競馬場コード PK
        string 開催回 PK
        string 開催日目 PK
        string レース番号 PK
    }
    SE["SE 馬毎レース情報"] {
        string レースキー PK
        string 馬番 PK
        string 血統登録番号 PK
    }
    HR["HR 払戻"] {
        string レースキー PK
    }
    H1["H1 票数1"] {
        string レースキー PK
    }
    H6["H6 票数6 3連単"] {
        string レースキー PK
    }
    O1_O6["O1〜O6 確定オッズ"] {
        string レースキー PK
    }
    HA["HA 票数A 枠単"] {
        string レースキー PK
    }
    OA["OA オッズA 枠単"] {
        string レースキー PK
        string 発表月日時分 PK "時系列で貯めるときだけ鍵に足す"
    }
    ND["ND 出走別着度数地方"] {
        string レースキー PK
        string 血統登録番号 PK
    }
    WF["WF 重勝式"] {
        string 開催年 PK
        string 開催月日 PK
        string 対象レース情報 FK "競馬場・回・日目・レース番号の組が3つ"
    }
    RA ||--|{ SE : "レースキー"
    RA ||--o| HR : "レースキー"
    RA ||--o| H1 : "レースキー"
    RA ||--o| H6 : "レースキー"
    RA ||--o{ O1_O6 : "レースキー（賭式ごとに1件）"
    RA ||--o| HA : "レースキー（枠単発売場のみ）"
    RA ||--o{ OA : "レースキー（枠単発売場のみ）"
    RA ||--o{ ND : "レースキー（出走馬ごとに1件）"
    WF }o--|{ RA : "対象レース情報"
```

`SE` が要です。**レースと馬をつなぐ唯一の表**で、1レース1頭につき1行あります。
`WF` はレースキーを持たず、開催年・開催月日と、中に並ぶ対象レース情報3つで `RA` に結びます。

## 馬と人のまわり

馬は**血統登録番号**（10桁）、騎手と調教師は**5桁のコード**で結びます。馬主と生産者は**コードと名前の組**で結びます（後述の落とし穴1）。

``` mermaid
erDiagram
    SE["SE 馬毎レース情報"] {
        string 血統登録番号 FK
        string 騎手コード FK
        string 調教師コード FK
        string 馬主コード FK
    }
    ND["ND 出走別着度数地方"] {
        string 血統登録番号 FK
        string 騎手コード FK
        string 調教師コード FK
        string 馬主コード FK
        string 生産者コード FK "6桁"
    }
    NU["NU 競走馬マスタ地方"] {
        string 血統登録番号 PK
        string 調教師コード FK
        string 馬主コード FK "000000 が多い"
        string 馬主名 FK "法人格無"
        string 生産者コード FK "8桁。先頭6桁で結ぶ"
        string 生産者名 FK "法人格無"
    }
    KETTO["NU の3代血統情報 子テーブル"] {
        string 血統登録番号 PK
        int 連番 PK
        string 繁殖登録番号 "繁殖馬マスタは届かない"
        string 馬名
    }
    NK["NK 騎手マスタ地方"] {
        string 騎手コード PK
        string 所属調教師コード FK "フリーは 00000"
    }
    NC["NC 調教師マスタ地方"] {
        string 調教師コード PK
    }
    NN["NN 馬主マスタ地方"] {
        string 馬主コード PK
        string 馬主名 PK "法人格無"
    }
    NB["NB 生産者マスタ地方"] {
        string 生産者コード PK "6桁"
        string 生産者名 PK "法人格無"
    }
    SE }o--|| NU : "血統登録番号"
    SE }o--|| NK : "騎手コード"
    SE }o--|| NC : "調教師コード"
    ND }o--|| NU : "血統登録番号"
    NU }o--|| NC : "調教師コード"
    NU }o--o| NN : "馬主コード＋馬主名"
    NU }o--o| NB : "生産者コードの先頭6桁＋生産者名"
    NK }o--o| NC : "所属調教師コード"
    NU ||--|{ KETTO : "血統登録番号"
```

`ND` も馬主・生産者のコードと名前を持ちますが、着回数の集計が目的の表なので、マスタを引く起点には `NU` を使います。

## JV-Data の形と地方の形

騎手・調教師・馬主は、JV-Data と同じ形（`KS` `CH` `BN`）と地方の形（`NK` `NC` `NN`）の両方が、**同じコードの同じ人物**で届きます。

``` mermaid
erDiagram
    NK["NK 騎手マスタ地方"] {
        string 騎手コード PK
    }
    KS["KS 騎手マスタ JV-Data の形"] {
        string 騎手コード PK
    }
    NC["NC 調教師マスタ地方"] {
        string 調教師コード PK
    }
    CH["CH 調教師マスタ JV-Data の形"] {
        string 調教師コード PK
    }
    NN["NN 馬主マスタ地方"] {
        string 馬主コード PK
        string 馬主名 PK
    }
    BN["BN 馬主マスタ JV-Data の形"] {
        string 馬主コード PK
        string 馬主名 PK
    }
    NK ||--|| KS : "騎手コード"
    NC ||--|| CH : "調教師コード"
    NN ||--|| BN : "馬主コード＋馬主名"
```

基本の属性（名前・生年月日・所属）はどちらにもあり、**競馬場別・距離別の着回数は地方の形だけが持ちます。**
地方の成績を見るなら地方の形を、JV-Data 向けの既存の SQL を流用するなら JV-Data の形を使います。両方を貯める必要はありません。
観測した3か月では、`KS` の騎手コード 265 のうち 263 が `NK` にもあり、名前も一致しました。

## 鍵の一覧

| 鍵 | 桁 | 持つレコード |
| :--- | ---: | :--- |
| レースキー | 16 | `RA` `SE` `HR` `H1` `H6` `O1`〜`O6` `HA` `OA` `ND` |
| 血統登録番号 | 10 | `NU` `SE` `ND` |
| 騎手コード | 5 | `NK` `KS` `SE` `ND` |
| 調教師コード | 5 | `NC` `CH` `NU` `SE` `ND` |
| 馬主コード＋馬主名(法人格無) | 6＋64 | `NN` `BN` `NU` `ND` |
| 生産者コード＋生産者名(法人格無) | 6＋70（`NU` は 8＋72。8 桁は 6 桁＋`00`） | `NB` `NU` `ND` |
| 開催年＋開催月日 | 8 | `WF` |

## 落とし穴

### 1. 馬主コード・生産者コードの `000000`

地方の馬主の約半数、生産者の約3分の2がコード `000000` です。**コードだけで結合すると別人が混ざります。**
`NN` と `NB` の1件を決める鍵は「コード＋名前（法人格無）」で、`NU` `ND` から引くときも、コードが `000000` なら名前で引きます。
`NU` の馬主名・生産者名は「法人格無」なので、`NN` `NB` の 法人格無 の列と合わせてください。

### 2. 生産者コードの桁が表で違う

`NU`（`DIFN`）の生産者コードは 8 桁・生産者名は 72 バイト、`NB`（`DIFF`）と `ND`（`SNAP`）は 6 桁・70 バイトです。
**8 桁のコードは、6 桁のコードの後ろに `00` を付けたもの**です。観測した 908 種類の 8 桁コードはすべて末尾が `00` で、
`ND` の 741 種類・`NB` の 521 種類の 6 桁コードは、すべて `NU` の先頭 6 桁に含まれていました。
`NU` から `NB` を引くときは、先頭 6 桁で結んでください。`000000` の生産者は名前で結びます。

### 3. 繁殖馬マスタが無い

`NU` の3代血統情報には繁殖登録番号（10桁）と馬名が並びますが、**繁殖馬マスタ（`HN`）は届きません。**
父母の名前は `NU` の中にあるものを使います。中央の繁殖馬マスタ（JV-Data の `HN`）と同じ番号体系なので、
中央のデータを持っていればそちらで引けます。ばんえいは3代目より先の馬名が空です。

## 中央との行き来

- `SE` の東西所属コードが `1`（美浦）`2`（栗東）の馬は、中央所属馬の地方交流競走への出走です。その馬のマスタ（`UM`）は地方競馬DATA では届かないので、JV-Data 側で引きます。
- 中央の `RA` `SE` にも 2000年以降の中央交流競走と、中央に出走した地方馬の過去走が入っています（JV-Data仕様書 4.9.0.1 p.31）。
  同じレースが両方にあるときは、競馬場コードが同じ（`30`〜`57`）なので鍵が一致します。
- ばんえい（`83`）は中央側にはありません。

## 時系列オッズの鍵

`0B41` `0B42` で届く `O1` `O2` と、`OA` には **発表月日時分** があり、同じレースに複数の断面が来ます。
貯めるときはレースキーに発表月日時分を足して1行にします（jvdata-store と同じ方針）。確定オッズ（`RACE` で届くもの）はレースキーだけで1件です。
